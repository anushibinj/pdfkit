# pdf-crop

Crops PDF pages and, optionally, **removes everything outside the crop
area**. Written in Rust, compiled to WebAssembly, and used by pdfkit's Crop
PDF tool (`src/tools/crop/`). Everything runs in the browser.

## Why this exists

A normal crop only sets each page's `CropBox`: viewers hide what lies
outside it, but it stays in the file, and anyone can bring it back by
resetting the box or extracting the text. PDFium (the engine the PDF Editor
uses) can set boxes, but its only content-removal API in the pinned
`@embedpdf/pdfium` 2.15.1 build, the experimental `EPDFText_RedactInRect`,
blanks an image's pixels **in every place the image is used**, including
pages that were never touched, and its stable `FPDFFormObj_RemoveObject`
corrupted shared form XObjects in our tests. So this crate does the removal
itself, at the level of content-stream operators.

## What "remove what's outside" does

| Content                          | Entirely outside       | Crossing the edge          |
| -------------------------------- | ---------------------- | -------------------------- |
| Text                             | deleted glyph by glyph | kept                       |
| Painted paths (lines, shapes)    | deleted                | kept                       |
| Images (XObject and inline)      | deleted                | kept whole (reported)      |
| Form XObjects                    | deleted                | replaced by a trimmed copy |
| Annotations (links, comments...) | deleted                | kept                       |
| Form fields (widgets)            | kept (reported)        | kept                       |

The `MediaBox` and `CropBox` become the crop area (`BleedBox`, `TrimBox`
and `ArtBox` are shrunk into it), the page thumbnail (`Thumb`) and private
application data (`PieceInfo`) are dropped, unreferenced objects (such as
the replaced content streams) are pruned, and the file is saved in full,
without earlier incremental revisions.

Principles:

- **Nothing visible is removed.** An object is deleted only when its
  conservative bounding box lies entirely outside the crop area. Glyph
  boxes are the union of the font's bounding box and a generous safety box.
- **Untouched bytes stay untouched.** Content streams are tokenised with
  exact byte spans; only the spans of deleted operators are replaced, and
  everything else is copied verbatim.
- **Kept glyphs do not move.** A deleted glyph is replaced by a `TJ` number
  that advances the pen exactly as far (ISO 32000-1, 9.4.4).
- **When unsure, keep.** Text in a font that cannot be measured exactly,
  streams that do not decode cleanly, and state that cannot be followed are
  left as they are, and counted in the report so the UI can say so.
- **Shared objects are never modified.** Content streams and forms used
  elsewhere get new copies (copy on write).
- **Encrypted files are refused**: saving them through lopdf would silently
  drop their protection.

### Readers that round glyph widths

The standard gives glyph widths as real numbers. PDFium (and so Chrome's
PDF viewer) truncates them to whole thousandths of an em. Deleting a glyph
replaces its exact width with a `TJ` number, so in PDFium the glyphs after
it on the same line can move by up to the dropped fractions. The report's
`maxTextShift` gives that bound in points (0 for fonts with whole-number
widths); the tool's verification allows exactly that much.

## Interface

The module has no imports and exports plain C functions (see `src/ffi.rs`):
`pdfcrop_alloc`, `pdfcrop_free`, `pdfcrop_run`, `pdfcrop_result_ptr/len`,
`pdfcrop_report_ptr/len`, `pdfcrop_clear` and `pdfcrop_abi_version`. The
plan is a little-endian `Float64Array` (see `src/plan.rs`):
`[1, flags, count, (pageIndex, left, bottom, right, top) x count]`, with
flag bit 0 meaning "remove what's outside".

## Building

The toolchain is pinned in `rust-toolchain.toml` (rustup installs it). From
the repository root:

```bash
pnpm wasm:crop
```

That runs `cargo build --release --target wasm32-unknown-unknown` and
copies the result to `crates/pdf-crop/dist/pdf_crop.wasm`, which is
committed so that building the site does not need Rust.
`scripts/copy-wasm.mjs` serves it from `/wasm/`.

Tests, formatting and lints:

```bash
cd crates/pdf-crop
cargo test
cargo fmt --check
cargo clippy --all-targets
```

`src/fonts/standard_data.rs` is generated by
`scripts/generate-standard-metrics.mjs` from `@pdf-lib/standard-fonts`
(widths) and `scripts/encodings.json` (encodings).
